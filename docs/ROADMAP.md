# 로드맵 · 로컬 CLI 인수인계

이 문서는 클라우드 세션에서 만든 현재 상태를 로컬 Claude Code CLI로 이어받기 위한 것이다. 프로젝트 규칙과 실행법은 루트 `CLAUDE.md`에 있고 CLI가 자동으로 읽는다.

## 로컬에서 시작하기

```bash
git clone https://github.com/yuangunn/nursing-TTS.git && cd nursing-TTS
npm install -g @anthropic-ai/claude-code    # 아직 없으면
claude                                       # 저장소 루트에서 실행 → CLAUDE.md 자동 로드
```

첫 세션에 붙여넣을 프롬프트:

```
CLAUDE.md와 docs/ROADMAP.md를 읽고 현재 상태를 파악해 줘. 그다음
1) backend 테스트를 돌려 통과하는지 확인하고,
2) app을 npm run dev로 띄워 처음 설정 마법사가 뜨는지 확인해서 스크린샷으로 보여 줘.
문제가 있으면 고치고, 없으면 ROADMAP의 M1 첫 작업(F5-TTS를 이 Mac에 설치하고 한국어 체크포인트로 합성 테스트)을 시작하자.
```

> 클라우드 세션과 달리 로컬 CLI는 이 Mac의 마이크·GPU(MPS)·설치된 앱(`/Applications/NursingTTS.app`)에 직접 닿는다. 복제 품질 실측은 로컬에서만 가능하다.

## 현재 상태 (v0.1.1-beta, 2026-10-14)

끝난 것
- 대본 생성 파이프라인: 6종 기록(S1~S6) + 간호 프로토콜 체크리스트, 4가지 말투, 요소별 말투 변형 ~1,350개와 관리 UI, 시그널 형식 8종 + 파서
- 오디오: 합성 병동 소음·SNR 믹싱, 장비/속도 증강, 간투사·숫자 정정, 긴 녹음 → 샘플 추출, Whisper CER 검증, LJSpeech/NeMo/Whisper 내보내기
- 앱: 처음 설정 마법사, 설치 진행률/ETA, 작업 순서 사이드바, 시작 가이드, 녹음/대량/목소리/결과물/말투/설정 화면
- 배포: GitHub Actions로 mac(arm64/x64 dmg·zip)·win(exe) prerelease 자동 생성

검증 안 된 것
- 실제 목소리 복제 품질 (F5-TTS, Qwen3-TTS, CosyVoice): GPU 없는 환경이라 어댑터만 작성

변경 후 1~2초 쉼 비율과 발화 비율이 실녹음과 같아졌다. 2초+가 두 배인 것은 모델이 덧붙이는 2~3초 꼬리 무음에 우리 쉼이 겹친 탓(최대 7초)이라 조각 양끝 무음을 잘라내도록 했다(`trim_silence`).

- 말속도는 실제 목소리로 복제하면 그 사람 속도를 따라간다(간호사7 5.7→5.7, 간호사8 5.2→5.4 음절/초). 속도 증강 기본값(0.92~1.08, 60%)은 바꿀 근거가 없어 **유지**
- **쉼이 결정적으로 달랐다**: 실제 녹음은 쉼의 1/4이 1~2초, 2초 넘는 것도 있는데 생성물은 1초 넘는 쉼이 드물었다(문단 사이 균등분포 0.35~0.8초뿐, 나머지는 모델이 쉼표에서 넣는 짧은 쉼). 문진형 녹음의 완충어는 어/음이 아니라 혹시·뭐·이제·좀이고, 받아쓰기형은 0이었다. 받아쓰기(nurse8)에는 "오전 1시, 정정하겠습니다 오후 1시 30분" 같은 숫자 정정이 실제로 있었다.
- [x] `tts/base.py`: 문단 → 문장 단위 합성, 문장 사이 쉼을 실측 로그정규(중앙값 0.6초·p90 1.6초·최대 3.5초, 문단 바뀔 때 ×1.6)로. `disfluency.py` 간투사 목록에 이제·뭐·혹시 추가(가중치는 실측 비율). 기본 흐트러짐 0은 받아쓰기형 실측과 같아 유지, 문진형은 level 2(문장당 18%)가 실측 ~2/분에 해당
- [x] 숫자·약어 읽기: 무작위 대본 280개의 `tts_text`에서 영문 잔여 토큰 50종 수집 → 사전 보강(수술명·컬쳐·call bell·NSAIDs·mg/dL·L/min…), 대소문자 무시 폴백, 천 단위 쉼표(1,800cc), 차트식 V/S 연쇄(120/80-76-20-36.8), q{n}h 일반화. `test_korean.py`에 사례 테스트 + 7종 템플릿×8시드 `tts_text`에 숫자·영문 0개 테스트
- [x] 소음: 실녹음 3개의 무음 구간(−52~−58 dBFS)을 이어 붙인 22초 룸톤을 "내 소음"으로 등록(앱 소리 옵션에 표시 확인). 실녹음 SNR ≈ 26 dB는 기본 소음 크기 35(= 24 dB)와 거의 같아 기본값 유지. 사용자가 고른 유튜브 영상에서 소리만 떠서(yt-dlp, m4a → afconvert) 네뷸라이저 60초·중환자실 배경음 120초(지속)·Mindray 모니터 알람 10초(이벤트)를 "내 소음"으로 등록. 파일은 저작권 때문에 `local_data/noise/`와 사용자 데이터 폴더에만 둔다. 회진은 실녹음 대신 `rounds.py`가 의사·환자·간호사 대화를 대본으로 만들어 시스템 TTS로 읽고 옆 침상 거리로 보낸 클립을 만든다(소리 옵션 "회진 대화 만들기" 버튼, 7초 소요, 24초 클립)
- [x] Whisper 검증: 기준 배치에서 Whisper가 영어 용어는 한글 발음으로, 숫자는 숫자로 적어 정답/발음 어느 층과도 안 맞았다(평균 CER 0.13). 전사를 `to_tts_text`로 변환한 세 번째 기준을 추가해 표기 차이를 걸러내자 0.09로 내려갔고 남은 차이는 진짜 오발음·오인식(삽입→"사빅", 억제대→"억제되는", 섬망→"선망"). "nasal"은 현장 발음 "나잘"로 변경
- [ ] 완료 기준: 간호사 2명에게 10개 블라인드 청취, "합성" 정답률 70% 이하 (사용자 진행)
