# 소리차트 (SoriChart) — 간호기록 음성 녹음 생성기

가상 환자의 간호기록을 **체크박스로 구성**하면, 등록된 간호사 목소리로 **발화하고 녹음 파일 + 정답 텍스트**를 저장하는 Windows / macOS 데스크탑 앱입니다. STT 학습용 데이터 제작을 목적으로 합니다.

- 기록 종류: 간호정보조사(S1; 서술형 또는 **대화형** — "어떻게 오셨어요?"로 시작해 간호사 질문·환자 대답을 두 목소리로, 정서평가·금연/금주 교육 포함) · 수술/검사 전 설명(S2) · 수술 후 기록(S3-1, POD 0 병실 도착 직후: 관찰→투약→처치→교육→배액관·도뇨관 관리) · 수술 후 상태기록(S3-2, 사정→노티→중재→재사정) · 퇴원간호(S4, 환자 확인→약→외래·입원 일정→건강관리→주의사항→상처·장치→알려야 할 상황) · 인수인계 SBAR(S5) · 경과기록(S6, 그날의 기록을 시각 순서로, 기록체). 서식마다 범주를 한 번씩만 말하고 한 환자의 사실에서 항목을 도출해 모순을 걸러냅니다
- 녹음 시작 시그널: `「[연도]년 [월]월 [일]일 [시간]시 [분]분 [환자 성명] 님 [기록종류] 기록입니다.」` (기록종류: 간호정보조사/퇴원간호/수술전설명/수술후설명/인계/경과기록 — 경과기록은 "수술 후 경과기록"·"항암 후 경과기록"; "님"은 있어도 없어도 인식)
- 현장 말투 다양화: 같은 체크 상태에서도 매번 다른 문장("혈압은 123에 90 측정되었고요, 열은 7도 1", "BP 123/90", "HTN"↔"고혈압"↔"하이퍼텐션")으로 생성. 말투(격식/구어/혼합/기록체 "~함·~됨") 선택, 어미 자동 확장, 말투 관리 탭에서 항목별 변형 편집
- 목소리 복제: 앱 안에서 의학용어가 많이 포함된 예시 대본을 읽어 녹음하거나, 실제 2~3분 녹음 파일(m4a/mp3/wav)을 올려 6~14초 샘플을 자동 추출(Whisper 전사 포함) → 여러 간호사 목소리 등록 → 로컬 오픈소스 모델로 그대로 발성
- 주변 소음: 병동에서 직접 녹음한 소음 8종(네뷸라이저, 주입 펌프 알람, 환자 모니터 알람, 산소 3L·5L·9L 흐름음, 병실 배경음 2개)과 룸톤이 설치본에 들어 있고, 켜진 클립이 각각 확률적으로 섞입니다(SNR 조절). 실제 병동 녹음 파일을 더 올릴 수 있고, 다른 등록 목소리로 "회진 대화"를 멀리서 들리게 섞는 옵션이 있습니다
- 가상 환자 대량 생성: 환자·날짜·상태를 무작위로 만들어 N개 일괄 생성
- 목소리 학습(미세조정): 한 사람의 녹음 10~30분과 확인한 전사로 그 사람 목소리를 학습해, 억양·말 빠르기·쉼까지 닮은 "(학습)" 목소리를 만듦(이 컴퓨터 안에서만)
- BYOK LLM(선택): Anthropic 또는 OpenAI 호환 API 키를 넣으면 규칙 기반 대본을 더 자연스럽게 다듬음


## 처음 실행 (설치 안내)

앱을 처음 켜면 **처음 설정 마법사**가 뜹니다. 순서는 `환경 점검 → 백엔드 설치 → 음성 엔진 → 첫 목소리 → 완료`이며 약 5분이 걸립니다.

- **환경 점검**: Python 3.10 이상, 디스크 여유 공간, 기존 설치 여부를 확인하고 없으면 설치 방법(brew / python.org)을 바로 안내합니다.
- **백엔드 설치**: 앱 데이터 폴더에 Python 가상환경을 만들고 패키지를 설치합니다. 단계별 진행률, 경과 시간, 예상 남은 시간이 표시되고 언제든 취소할 수 있습니다. 기본 설치는 2~4분, Qwen3-TTS 복제 엔진을 함께 설치하면 10~25분(패키지 약 2 GB + 모델 약 4.5 GB)입니다. pip이 버전 충돌로 제자리걸음을 하면 자동으로 중단하고 이유를 알려 줍니다.
- **음성 엔진**: 처음에는 "자동"으로 두면 됩니다. 복제 엔진이 없으면 시스템 음성으로 전체 흐름을 먼저 확인할 수 있습니다.
- **첫 목소리**: 대본을 읽어 10초 샘플을 등록합니다. 마이크가 없으면 건너뛰고 나중에 "1 · 목소리 등록"에서 하면 됩니다.

마법사가 끝나면 왼쪽 메뉴가 작업 순서(1 목소리 등록 → 2 대본 생성 → 3 녹음 만들기 → 4 대량 생성 → 5 결과물·검수)대로 정렬되어 있고, 첫 화면 위의 **시작 가이드**가 다음에 할 일을 알려 줍니다. 설정 탭의 "처음 설정 다시 보기"로 언제든 마법사를 다시 열 수 있습니다.

## 결과물

`출력폴더/{시그널발화시각}_{환자명}.wav` 와 같은 이름의 `.txt`(발화한 정답 텍스트), `.json`(구조화 데이터 + TTS 발음 텍스트 + 소음 이벤트 + 메타)이 함께 저장됩니다.

```
20261018_1110_홍길동.wav
20261018_1110_홍길동.txt   ← "2026년 10월 18일 오전 11시 10분 홍길동 님 인계 기록입니다. 과거력 HTN, 당뇨 있고 ..."
20261018_1110_홍길동.json  ← spoken_text / tts_text / structured(form) / noise.events / seed ...
```

내보낸 데이터셋은 `출력폴더/_exports/<이름>/`에 `wavs/`(16 kHz mono) + `metadata.csv`(LJSpeech) + `manifest_*.jsonl`(NeMo) + `whisper_*.jsonl` + `dataset.csv` + `report.json` + `README.md`(데이터셋 카드)로 저장됩니다.

`tts_text`는 숫자·약어를 모두 한글 발음으로 바꾼 텍스트("혈압 백이십삼 에 구십, 에이치티엔")로, 모델이 실제로 읽은 발음의 기록입니다.

## 구조

```
backend/   Python (FastAPI) – 대본 생성, 한국어 발음 변환, TTS 어댑터, 소음 합성/믹싱, 목소리/소음 라이브러리, 배치
app/       Electron + React – 데스크탑 UI (백엔드를 자동 실행)
scripts/   설치 스크립트, 커스텀 TTS 서버 예제
```

## 설치

요구 사항: **Python 3.10+**, **Node.js 18+**. 목소리 복제 모델을 로컬에서 돌리려면 NVIDIA GPU(CUDA) 또는 Apple Silicon(MPS)을 권장합니다 (CPU도 동작하지만 매우 느림).

### 1) 백엔드

```bash
# macOS / Linux
./scripts/setup-backend.sh          # 기본
./scripts/setup-backend.sh --qwen   # + Qwen3-TTS 내장 목소리 복제 엔진

# Windows (PowerShell)
.\scripts\setup-backend.ps1
.\scripts\setup-backend.ps1 -Qwen
```

### 2) 앱 실행 (개발 모드)

```bash
cd app
npm install
npm run dev
```

앱이 뜨면 `backend/.venv`의 Python으로 백엔드(`http://127.0.0.1:8765`)를 자동 실행합니다. 설정 탭에서 백엔드 로그와 엔진 상태를 볼 수 있습니다.

### 3) 설치 파일 만들기 (선택)

```bash
cd app
npm run dist:win    # Windows NSIS 설치 파일 → app/release/
npm run dist:mac    # macOS dmg
```

설치 버전은 처음 설정 마법사가 앱 데이터 폴더에 Python 가상환경을 만들어 씁니다(인터넷 필요). 인터넷이 없는 PC는 아래 4)의 `-offline` 설치 파일이나 오프라인 번들을 쓰면 됩니다.

### 4) 인트라넷(인터넷 없는 PC) 설치 — 오프라인 번들

설치 후 Python이나 pip, 모델을 내려받을 수 없는 PC용입니다. 인터넷이 되는 PC에서 번들 zip을 만들어 USB 등으로 옮깁니다.

```bash
# 인터넷 되는 PC (같은 OS·아키텍처여야 함)
scripts/build-offline-bundle.sh --qwen            # macOS/Linux: Python + 패키지 + Qwen3-TTS/faster-whisper
scripts/build-offline-bundle.sh --qwen --models   # + 모델 파일(약 5 GB)까지 한 번에
powershell -ExecutionPolicy Bypass -File scripts\build-offline-bundle.ps1 -Qwen          # Windows (CPU PyTorch)
powershell -ExecutionPolicy Bypass -File scripts\build-offline-bundle.ps1 -Qwen -Cuda    # Windows + NVIDIA (cu128, 약 3 GB)
```

`--data`(Windows `-Data`)를 붙이면 이 PC의 등록 목소리·소음 클립(앱 데이터 폴더의 `voices/`, `noises/`)도 함께 들어가 다른 PC에 그대로 옮겨집니다. 번들은 `dist-offline/nursing-tts-offline-<os>-<arch>[-qwen][-models][-data].zip`로 만들어집니다(안에 relocatable CPython `python/`, 선택 `models/hub/`, `bundle.json`). 인트라넷 PC에서는 앱 설치 파일을 깔고 **처음 설정 마법사의 "백엔드 설치" 단계** 또는 **설정 → 백엔드**에서 "📦 오프라인 번들(zip) 가져오기"로 그 zip을 고르면, 앱 데이터 폴더 `offline/`에 풀려 그 Python으로 백엔드가 뜹니다. 모델을 번들에 넣지 않았다면 설정 → 로컬 모델의 폴더에 `models--Qwen--Qwen3-TTS-12Hz-1.7B-Base`, `models--Systran--faster-whisper-small` 폴더를 복사하세요. GitHub Actions의 "Offline bundle" 워크플로로도 mac(arm64/x64)·Windows(CPU) 번들을 릴리스에 올릴 수 있습니다(2 GB 넘는 CUDA 번들은 로컬에서 만들어 옮김).

모든 설치 파일에는 기본 목소리 15명(Zeroth-Korean, CC BY 4.0)과 병동 소음 클립 10개(병동 실녹음 8종 + 룸톤 + 회진 대화)가 들어 있어 첫 실행 때 데이터 폴더에 자동으로 들어갑니다(`backend/nursing_tts/assets/seed/`, 출처는 `ATTRIBUTION.md`). 시드가 새 버전으로 바뀌면 다음 실행 때 옛 시드 클립은 빠지고 새 클립이 들어가며, 직접 등록한 목소리·클립은 그대로입니다.

**한 번에 설치되는 "-offline" 설치 파일**: 릴리스마다 `NursingTTS-offline-<버전>-mac-arm64.dmg`, `-win-x64.exe`도 함께 올라갑니다(Intel Mac용은 없음: PyTorch가 x86_64 macOS 휠을 더 이상 제공하지 않음). 앱 안(`resources/offline`)에 Python과 모든 패키지, Qwen3-TTS 복제 스택(Windows는 CPU PyTorch)이 들어 있어 설치만 하면 pip 없이 백엔드가 뜹니다. 들어 있지 않은 것은 모델 파일(약 5 GB, 설정 → 로컬 모델 폴더에 복사 또는 `--models` 번들)과 이 PC의 목소리·소음(`--data` 번들)입니다. NVIDIA GPU용 CUDA PyTorch는 설치 파일 크기 한도 때문에 `.ps1 -Qwen -Cuda` 번들로 따로 옮깁니다.

## TTS 엔진

| 엔진 | 목소리 복제 | 비고 |
|---|---|---|
| **Qwen3-TTS** (`qwen`) | O | 내장 한국어 복제 (Apache-2.0, 기본 1.7B). 마법사 "목소리 복제 엔진 포함" 또는 `pip install -r backend/requirements-qwen.txt`. Apple Silicon(MPS)·NVIDIA 권장 |
| **커스텀 HTTP** (`http`) | O | Fish Speech / OpenAudio, CosyVoice 2, XTTS 등 원하는 모델을 `scripts/example_tts_server.py` 계약으로 감싸 연결 |
| 시스템 TTS (`system`) | X | macOS `say`, Windows SAPI, Linux espeak-ng. 파이프라인 확인용 |
| 무음 (`silent`) | X | 음성 없이 파일/텍스트 파이프라인 테스트용 |

`자동` 선택 시 Qwen3-TTS → HTTP → 시스템 → 무음 순으로 사용 가능한 엔진을 고릅니다. 모델은 기본 설정에서 10분 쉬면 메모리에서 내려가고 다음 합성 때 다시 올라옵니다(설정에서 조절).

### 한국어를 지원하는 로컬 목소리 복제 모델

2026년 기준으로 한국어를 공식 지원하면서 오픈 가중치로 로컬 실행이 가능한 zero-shot 복제 모델입니다. 모두 `scripts/servers/`의 래퍼로 바로 연결할 수 있습니다 (각 모델은 의존성이 달라 **별도 가상환경**에서 서버로 띄우는 방식을 권장).

| 모델 | 라이선스 | 한국어 | 참조 음성 | 래퍼 | 비고 |
|---|---|---|---|---|---|
| **Qwen3-TTS** (Alibaba, 0.6B/1.7B) | Apache-2.0 | 10개 언어 중 공식 지원 | 3초~ | 내장 엔진 `qwen` 또는 `qwen3_tts_server.py` | **기본 내장 엔진**. M4 Mac(MPS)에서 1.7B 실시간 대비 약 2.3배, 0.6B 약 1.9배. 앱 안에서 **목소리 학습(LoRA 미세조정)** 지원 |
| **Chatterbox Multilingual v3** (Resemble AI) | MIT | 23개 언어, `ko` | 5~10초 | `chatterbox_server.py` | 감정 과장(exaggeration) 조절 가능, 설치 간단 |
| **Fun-CosyVoice3 / CosyVoice2** (Alibaba) | Apache-2.0 | 9개 언어 중 공식 지원 | 3~10초 | `cosyvoice_server.py` | 저장소 클론·모델 다운로드 필요, 스트리밍 지원 |
| **GPT-SoVITS v2+** | MIT | 한/영/일/중/광둥 | 5초 zero-shot, 1분 few-shot 파인튜닝 | (자체 API 서버 `api_v2.py` 사용) | 간호사별 1분 데이터로 **파인튜닝**하면 가장 비슷한 목소리 |
| ~~F5-TTS~~ | CC-BY-NC | 기본 vocab에 한글 없음 | — | (제거됨) | 공개 한국어 체크포인트가 없어 0.1.2에서 뺐습니다 |

실행 예:

```bash
# Qwen3-TTS (별도 venv; Apple Silicon은 MPS bf16으로 자동 실행, M4에서 0.6B 모델 RTF 약 1.9)
python3.12 -m venv ~/.venvs/nursing-qwen && ~/.venvs/nursing-qwen/bin/pip install -U qwen-tts fastapi uvicorn python-multipart soundfile
~/.venvs/nursing-qwen/bin/python scripts/servers/qwen3_tts_server.py --port 8081
# 앱 설정 → 커스텀 HTTP TTS 서버 URL: http://127.0.0.1:8081/synthesize
```

래퍼는 각 모델의 공식 README/모델 카드에 적힌 API 그대로 호출하며, 이 저장소에서는 GPU가 없어 실제 합성까지는 검증하지 못했습니다. 모델 버전이 바뀌어 인자명이 달라지면 래퍼 파일의 `synthesize()` 한 함수만 고치면 됩니다.

### 원격 GPU에서 합성하기

내장 엔진은 백엔드가 도는 PC에서 합성합니다. GPU가 다른 PC(예: NVIDIA 노트북)에 있으면 거기서 `scripts/servers/qwen3_tts_server.py`를 띄우고 설정 → 커스텀 HTTP TTS 서버 URL을 그 PC 주소로 바꾸면 됩니다. 수천 건을 양산할 때 유리합니다.

### 커스텀 HTTP TTS 서버 계약

```
POST {url}  multipart/form-data
  text       : 읽을 한국어 발음 텍스트
  ref_audio  : 참조 wav (등록된 목소리 샘플)
  ref_text   : 참조 음성의 전사
  seed       : 정수 (선택)
→ 200, body = audio/wav
GET {url의 상위 경로}/health → 200
```

`scripts/example_tts_server.py`의 `synthesize()`만 교체하면 됩니다.

## 사용 흐름

1. **목소리 등록** 탭 → 목소리 추가 → 예시 대본(의학용어 포함, 8~15초)을 선택하고 녹음 → 3~5개 샘플 권장. "이 목소리로 합성 테스트"로 확인
2. **대본 생성** 탭 → 🎲 무작위 여러 개(기록 종류·말투·개수, 간호정보조사는 "환자 대답 포함(대화형)"과 "간호진단 문장 포함" 체크) 또는 ✎ 직접 설정(가상 환자·상태 체크) → 읽어 보며 🗣 같은 대본 다른 말투로 / 🔀 다른 문구 / ✨ LLM 다듬기 / ✎ 직접 고치기 → 병동에서 안 쓰는 문장은 표시 → 🧺 바구니에 담기
3. **녹음 만들기** 탭 → 바구니에서 대본 선택 → 간호사 목소리(대화형이면 환자 목소리도: 자동/간호사 변조/지정) → 소음·증강 옵션 → 변형 수 → 🎙 발화 + 녹음 저장
4. **대량 생성** 탭 → 개수·기록 종류·목소리·소음 비율 지정 → 시작. 결과는 출력 폴더의 하위 폴더에 저장
5. **결과물·검수** 탭 → 듣고 승인/반려, CER 확인, 데이터셋 내보내기. **설정** 탭 → 엔진/장치/체크포인트, 출력 폴더, 샘플레이트(STT용 16 kHz), LLM BYOK, 동작 원리 안내, 로컬 모델 위치
6. (선택) **그 밖에 → 목소리 학습** → 한 사람의 녹음으로 학습 데이터 만들기 → 전사 확인 → 학습 → 목소리 목록에 생긴 "(학습)" 목소리로 녹음 (아래 절)

변경 이력은 `docs/RELEASE_NOTES.md`, 설치 파일은 [Releases](https://github.com/yuangunn/nursing-TTS/releases)에 있습니다.

## 목소리 학습 (미세조정)

참조 클립 10초를 흉내 내는 기본 방식(제로샷 복제)은 목소리는 비슷해도 실제 간호사보다 **빠르고 쉼이 거의 없어** 기계적으로 들립니다(간호사A 측정: 말하는 동안 7.2음절/초 vs 실제 5.6, 쉼 포함 5.5 vs 3.7). 한 사람의 녹음을 모아 학습하면 그 사람의 음색·말 빠르기·쉼을 더 닮은 목소리가 됩니다. 학습은 이 컴퓨터 안에서만 하고 녹음은 밖으로 나가지 않습니다.

**순서** (사이드바 "그 밖에 → 목소리 학습")
1. **학습 데이터 만들기** — 등록된 목소리의 클립을 그대로 쓰거나(클립마다 그 클립의 방 소리를 앞뒤로 0.25초 붙임), 긴 녹음 파일(여러 개 가능)을 올리면 쉼마다 3~14초로 자르고 Whisper로 초안 전사를 붙입니다.
2. **전사 확인** — 클립마다 들어 보고 **말하려던 대로가 아니라 들리는 그대로** 고칩니다("어", "음", 고쳐 말한 부분 포함, 숫자·영어 약어는 소리 나는 대로 한글로: "비피 백이십에 팔십"). 쓸 클립은 "쓰기", 다 들어 본 클립은 "확인"에 체크합니다. 틀린 전사는 학습을 망칩니다.
3. **학습 시작** — 진행률·남은 시간·취소가 보입니다. 학습 중에는 녹음을 만들 수 없고, 녹음 작업이 돌고 있으면 학습을 시작할 수 없습니다.
4. 끝나면 목소리 목록에 **"○○ (학습)"** 목소리가 생깁니다. 녹음 만들기·대량 생성에서 다른 목소리처럼 고르면 됩니다. 지우면 학습 결과도 함께 지워집니다.

**녹음할 때**
- 본인 동의를 먼저 받습니다(연구라면 IRB). 학습한 모델도 그 사람의 목소리를 만들 수 있으니 원본 녹음처럼 비공개로 보관합니다.
- 실제 환자 기록을 읽을 때는 **가명으로 바꾼 뒤** 읽습니다. 녹음에 실제 환자 정보가 남으면 안 됩니다.
- 읽기만 하지 말고 키워드만 보고 평소처럼 인계·구술하는 부분을 섞어야 말버릇이 학습됩니다. **10분이면 시험해 볼 수 있고 30분 이상이 좋습니다.**
- 조용한 방, 같은 마이크, 같은 거리. 병동 소음은 녹음을 만들 때 따로 섞습니다.

**어떻게 학습하나**
- 기본 모델(Qwen3-TTS 1.7B Base)은 그대로 두고 작은 어댑터(LoRA, rank 16)만 학습합니다. 모델 전체를 학습하는 공식 방식은 1.7B에서 16 GB가 넘어 16 GB Mac·12 GB GPU에 들어가지 않습니다. M4 Mac에서 6분 분량 1회 학습에 약 1분, 메모리 약 5 GB(NVIDIA GPU는 더 빠름).
- 클립 10%를 떼어 두고 매 회차 검증 손실을 재서 **가장 좋은 회차**를 저장합니다(간호사A 6분: 4회째가 최저, 그 뒤로는 과적합).
- 저장되는 것은 어댑터와 화자 임베딩뿐(수십 MB)이라 화자마다 4.5 GB 모델이 쌓이지 않습니다. `앱 데이터 폴더/finetune/`(`datasets/`, `models/<id>/adapter.pt·progress.jsonl·train.log`).

**간호사A 6분으로 해 본 결과** (같은 문장 5개, 제로샷 복제 → 학습)
| | 제로샷 복제 | 학습한 목소리 | 실제 녹음 |
|---|---|---|---|
| 화자 유사도(x-vector) | 0.964 | **0.983** | 0.987(실제끼리) |
| 말하는 동안 속도(음절/초) | 7.2 | **6.0** | 5.6 |
| 받아쓰기 오류율(CER) | 0.13 | 0.15 | — |

데이터가 6분뿐이고 일부 전사가 확인하지 않은 자동 전사라, 가끔 문장 끝에 군말이 붙거나 앞이 웅얼거리고 받아쓰기 오류가 조금 많습니다. 확인한 전사로 30분 이상 모으면 나아질 것으로 봅니다.

## 트러블슈팅

지금까지 실제로 겪은 문제와 해결입니다. 버전은 고쳐진 버전이니, 증상이 보이면 먼저 앱을 최신으로 올리세요.

### 설치·실행
- **macOS에서 "확인되지 않은 개발자"로 앱이 안 열림** — 서명·공증 없는 베타 빌드입니다. Finder에서 앱을 우클릭 → 열기, 또는 `xattr -dr com.apple.quarantine /Applications/NursingTTS.app`.
- **마법사가 Python이 없다거나 설치가 안 됐다고 함** — Python 3.10 이상이 필요합니다(macOS `brew install python`, Windows python.org 설치 때 "Add to PATH" 체크). 예전 빌드가 만든 Python 3.9 가상환경이 앱 데이터 폴더에 남아 있으면 "설치 안 됨"으로 보고 마법사가 다시 만듭니다.
- **백엔드 설치가 한참 제자리걸음** — pip이 버전 충돌로 같은 단계를 되풀이하면 마법사가 감지해 멈추고 이유를 보여 줍니다. 네트워크(프록시)를 확인하고 다시 시도하거나, 인터넷이 없는 PC라면 `-offline` 설치 파일·오프라인 번들을 쓰세요.
- **인트라넷 PC에서 모델을 못 받음** — `-offline` 설치 파일에도 모델(약 5 GB)은 없습니다. `build-offline-bundle --models` 번들로 옮기거나 설정 → 로컬 모델 폴더에 `models--Qwen--Qwen3-TTS-12Hz-1.7B-Base`, `models--Systran--faster-whisper-small`을 복사합니다. Intel Mac용 `-offline` 설치 파일은 없습니다(PyTorch가 x86_64 macOS 휠을 내지 않음). NVIDIA GPU용 CUDA PyTorch(cu128)는 크기 한도 때문에 `.ps1 -Qwen -Cuda` 번들로 따로 옮깁니다(RTX 50 시리즈는 cu128 필수).
- **"백엔드 꺼짐" 또는 다른 프로그램과 포트 충돌** — 백엔드는 8765를 쓰고, 다른 프로그램이 8765를 차지하고 있으면 8766부터 빈 포트로 옮깁니다. 앱은 `/api/health`가 우리 백엔드로 답하는 경우에만 이미 떠 있는 백엔드를 재사용합니다. 설정 → 백엔드에서 로그를 보고 "다시 시작"을 누르세요.
- **새 버전 배너가 안 뜸** — 릴리스 태그가 앱 버전보다 높아야 뜹니다. "이 버전 알림 받지 않기"를 눌렀다면 설정 → 업데이트 확인에서 되돌립니다.

### 녹음이 멈추거나 느릴 때
- **녹음 한 건이 몇 시간 동안 끝나지 않음, 메모리 20 GB 이상** — 끝맺음을 못 낸 문장 하나가 함께 합성하던 묶음 전체를 모델 한도(약 11분 분량)까지 끌고 가고, 묶음을 한꺼번에 파형으로 바꾸며 메모리가 튀던 문제입니다. v0.1.23에서 문장 길이에 맞춘 생성 상한과 문장별 디코딩으로 고쳤습니다(같은 기록 14 GB → 7.7 GB).
- **16 GB Mac에서 대량 생성이 점점 느려짐** — 스왑 때문입니다. v0.1.17부터 녹음마다 GPU 캐시를 돌려주고 참조 캐시를 6개로 제한합니다. Mac에서는 소량씩, 수천 건 양산은 NVIDIA PC에서(원격 GPU, `scripts/servers/qwen3_tts_server.py`) 권합니다. 다른 앱(브라우저 등)이 메모리를 많이 쓰고 있으면 몇 배 느려집니다.
- **메모리를 볼 때** — macOS에서는 활동 상태 보기의 "메모리" 또는 `top -l 1 -pid <PID> -stats mem`(footprint)을 보세요. `ps`의 RSS는 GPU(통합 메모리) 사용량을 못 보여 줘서, 1 GB로 보이던 백엔드가 실제로는 23 GB였던 적이 있습니다.
- **Mac이 잠자기에 들어가면 작업이 멈춤** — 잠자기 동안 MPS 작업이 멈춥니다. 대량 생성·학습 중에는 잠자기를 끄고, 멈췄다면 설정 → 백엔드 "다시 시작".
- **첫 녹음이 수십 초 걸림** — 모델은 10분 쉬면 메모리에서 내려가고 다음 합성 때 다시 올라옵니다(정상, 설정에서 시간 조절).
- **"목소리 학습 중에는 녹음을 만들 수 없습니다"** — 학습이 GPU 메모리를 쓰는 동안은 녹음을 막습니다. 학습이 끝나거나 취소한 뒤 다시 시도하세요.

### 녹음 품질
- **문장 첫 낱말이 빠짐**("양치, 탄툼 가글"의 양치, "환자, 보호자 모두"의 환자) — 등록 때 바짝 잘린 참조 클립(말 끝 뒤 무음이 거의 없음)과 마침표 없는 전사 때문에 모델이 새 문장의 첫 낱말을 클립의 이어지는 말로 보고 삼켰습니다. v0.1.26부터 합성 전에 참조 클립의 음량을 맞추고 끝에 0.5초 무음과 마침표를 붙입니다(원본 파일은 그대로).
- **"~십니다"가 "~십니ㄷ"처럼 끝이 잘림** — v0.1.26부터 모델에 넣는 문장 끝을 "..."으로 바꿔 마지막 음절까지 읽게 합니다(정답 텍스트는 마침표 그대로). 그래도 잘리는 문장이 들리면 알려 주세요.
- **문장마다 소리 크기가 들쭉날쭉** — 한 목소리의 참조 클립끼리 말소리 크기가 16 dB까지 달랐고 재합성은 다른 클립을 씁니다. v0.1.26부터 문장마다 말소리를 같은 크기로 맞춘 뒤 이어 붙입니다.
- **한 문장을 수십 초 더듬거나 엉뚱한 소리가 섞임** — v0.1.24부터 문장별 받아쓰기 검증에서 실패한 문장은 **같은 목소리의 다른 참조 클립**으로 다시 합성하고, 그래도 못 읽는 문장이 남으면 그 녹음은 "불통과"로 표시되어 데이터셋 내보내기에서 빠집니다. 결과물·검수에서 확인하고 다시 합성하세요.
- **"너무 기계음 같다"** — 제로샷 복제가 실제 간호사보다 빠르고 쉼이 적기 때문입니다(위 "목소리 학습" 절의 측정). 목소리 학습을 쓰거나, 증강 패널의 구어 흐트러짐(추임새·말 반복·숫자 정정)을 켜세요.
- **서술형 기록인데 질문하는 억양** — 복제는 참조 클립의 억양을 따라갑니다. 질문형 전사("…있으세요?")가 달린 클립은 대화형 간호정보조사에만 쓰이고 나머지는 서술형 클립을 씁니다. 참조 클립 전사가 실제와 다르면 목소리 등록 화면에서 고치세요(전사가 틀리면 말투가 흔들립니다; `scripts/recheck_samples.py`로 일괄 확인).
- **소음이 겹겹이 쌓이거나 무음 구간에서 볼륨이 툭 떨어짐** — v0.1.15부터 알람 같은 이벤트 소음은 8~20초 토막으로 겹치지 않게, 합쳐서 녹음의 1/3 정도까지만 들어갑니다. 소음을 꺼도 아주 작은 룸톤과 약한 울림이 깔려 무음 구간이 끊기지 않습니다.
- **받아쓰기 오류율(CER)이 높게 나오는데 들어 보면 멀쩡함** — 영어 약어(Rt arm 20G IV, SpO2)·숫자 표기 차이 때문에 Whisper CER이 부풀려집니다. 정답·발음 텍스트·전사의 발음 변환 세 기준 중 가장 낮은 값을 쓰지만, 약어가 많은 기록은 0.15~0.20도 정상일 수 있으니 들어 보고 판단하세요.
- **시스템 음성(macOS say)이 처참함** — 시스템 TTS는 복제가 아니라 흐름 확인용입니다. 실제 녹음은 Qwen3-TTS 복제 엔진으로 만드세요.

### 목소리 등록
- **m4a 파일이 안 읽힘(Windows)** — m4a·aac는 ffmpeg가 있어야 읽습니다(macOS는 내장 afconvert로 읽음). wav로 바꿔 올리거나 ffmpeg를 설치하세요.
- **원음 참조 클립을 지우고 싶음** — 제로샷 복제는 합성할 때마다 참조 음성을 쓰므로 지우면 그 목소리를 쓸 수 없습니다. 목소리 등록 화면에서는 생성 예시만 보이고 원음 목록은 "고급: 참조 클립 관리"에 접혀 있습니다.

### 목소리 학습
- **학습이 아주 느림** — 스왑 때문일 가능성이 큽니다. 처음 만든 학습 코드는 11 GB를 쓰며 스왑 6 GB에 걸려 한 회차가 10분 넘게 끝나지 않았고, 메모리 절약 설정(중간 계산 다시 하기·배치 1·bf16)으로 약 5 GB, 회차당 1분이 되었습니다. 학습 중에는 다른 무거운 앱을 닫으세요. GPU가 없으면(CPU) 현실적인 시간 안에 끝나지 않습니다.
- **학습한 목소리가 웅얼거리거나 문장을 끝내지 못함** — Qwen 공식 미세조정 스크립트(`finetuning/sft_12hz.py`)를 지금 라이브러리(transformers 4.57)에서 그대로 쓰면 텍스트 투영을 건너뛰고 정답이 두 번 밀려, 72초 상한까지 웅얼거리는 모델이 나옵니다. 앱은 생성과 같은 정렬로 손실을 직접 계산합니다(`finetune._loss`). 그래도 이상하면 데이터가 적거나 전사가 틀린 경우입니다 → 전사 확인, 30분 이상.
- **학습한 목소리가 느리거나 끝에 없는 소리가 붙음** — 데이터가 적어 과적합된 경우입니다. 앱이 검증 손실로 가장 좋은 회차를 고르지만, 근본 해결은 확인한 전사의 데이터를 늘리는 것입니다. 생성 온도를 낮추면 오히려 더 느려지고 가끔 크게 실패해 기본값(0.9)을 씁니다.
- **학습이 "오류"로 끝남** — 목소리 학습 화면의 학습한 목소리 표에 메시지가 나옵니다. 자세한 로그는 `앱 데이터 폴더/finetune/models/<id>/train.log`.
- **v0.1.26 이하로 되돌리자 목소리 목록이 비어 보임** — 옛 버전은 학습 목소리 파일의 새 항목(`model`)을 읽지 못해 목록 전체를 못 불러왔습니다. v0.1.27부터는 모르는 항목이 있어도 읽습니다. 옛 버전을 써야 하면 `voices/`에서 학습 목소리 폴더를 잠시 다른 곳으로 옮기세요.

### 결과물·내보내기
- **녹음이 내보내기에서 빠짐** — 검증 "불통과"(전체 CER 기준 초과 또는 다시 합성해도 못 읽은 문장)인 녹음은 데이터셋에서 빠집니다. 결과물·검수에서 CER 배지·사유를 보고 다시 합성하세요.
- **긴 녹음이 `_p01`, `_p02`로 나뉨** — Whisper 학습 창(30초)에 맞춰 문장 경계에서 자릅니다(`max_clip_sec`). 내보낸 폴더는 `scripts/check_export.py`로 검사할 수 있습니다.

### 개발 환경 (개발자용)
- **Node 24에서 `npm ci` 뒤 Electron이 안 뜸** — `node_modules/electron/dist`만 있고 `path.txt`가 없으면 Electron 바이너리 추출이 조용히 멈춘 것입니다. `~/Library/Caches/electron/*/electron-v*.zip`을 `ditto -x -k`로 `dist/`에 풀고 `path.txt`에 `Electron.app/Contents/MacOS/Electron`을 쓰세요.
- **백엔드 코드를 고쳤는데 앱에 반영이 안 됨** — 개발 앱은 시작할 때 백엔드를 띄우므로 Electron을 다시 띄워야 합니다.
- **패키징 앱을 시험하는데 개발용 백엔드를 재사용함** — 앱은 떠 있는 우리 백엔드를 재사용합니다. 시험은 `NURSING_TTS_PORT=8790` 같은 전용 포트와 `NURSING_TTS_DATA` 격리 폴더로 하고, 끝나면 남은 백엔드를 끄세요.
- **`pkill -f nursing_tts`가 내 셸까지 죽임** — `pgrep -f "[n]ursing_tts"`처럼 대괄호 트릭을 쓰세요.
- **`backend/nursing_tts/` 폴더 안에서 파이썬을 실행하면 이상한 ImportError** — 그 폴더의 `signal.py`가 표준 라이브러리 `signal`을 가립니다. 다른 폴더에서 실행하세요(`python -I` 권장).
- **테스트를 돌릴 때마다 임시 폴더가 쌓임** — 2026-10-17 이전에는 실행마다 약 125 MB씩 11 GB까지 쌓였습니다. 지금은 `tests/conftest.py`가 세션 끝에 지웁니다.
- **빌드 산출물이 커밋에 섞임** — 로컬 번들 7,561개 파일이 `git add -A`로 main에 올라간 적이 있습니다. 산출물(`app/offline-build/`, `dist-offline/` 등)은 `.gitignore`에 있고, 커밋 전에 `git status`를 보고 파일을 지정해 `git add` 하세요. 테스트 녹음·실제 음성은 `backend/local_data/`(gitignore)에만 둡니다.
- **오프라인 번들 CI 잡 실패** — 번들 스크립트는 상대 `--out`을 저장소 루트 기준으로 풉니다. CI(app/ 작업 폴더)에서는 절대 경로와 `--no-zip`을 씁니다.

## 개발

```bash
cd backend && .venv/bin/python -m pytest        # 백엔드 테스트 (발음 변환, 문법, 생성기, 믹서, API)
cd app && npm run typecheck && npm run build    # 프론트엔드
```

브라우저만으로 UI를 확인하려면 백엔드를 `python -m nursing_tts`로 띄우고 `npm run dev` 후 `http://localhost:5173`을 열면 됩니다 (Electron 전용 기능인 폴더 열기 등은 비활성).

### 발화 템플릿 수정

`backend/nursing_tts/templates/s*.py`에 항목·선택지·문장 변형이 선언되어 있습니다. 각 선택지에 여러 문장을 넣으면 생성 시 무작위로 선택되며, 쉼표(`,`)로 끝나는 문장은 다음 항목과 이어지는 연결형("~하시구요,")으로 취급됩니다. 약어 발음은 `korean.py`의 `ABBREVIATIONS`에 추가하면 됩니다.
